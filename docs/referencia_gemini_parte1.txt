Para construir una plataforma robusta, escalable y pensada para la realidad de las productoras de eventos (donde el control de flujo en puerta y la merma en barra definen si el evento deja ganancias o pérdidas), la arquitectura debe estar diseñada como un  SaaS Multi-Tenant  (cada productora/evento es un espacio aislado) con soporte  Offline-First  (crítico porque en muchas locaciones o fiestas la señal móvil falla justo al momento de escanear QRs).
Aquí tienes la arquitectura técnica completa, el modelo de base de datos, los flujos lógicos y la estructura del sistema listo para empezar a programar.
1. Arquitectura y Stack Tecnológico Recomendado
Para evitar costos fijos altos y tener control total de los datos y correos:
Frontend (Web App / PWA):   React (Next.js) o Vue/Nuxt  +  Tailwind CSS . Convertirla en PWA (Progressive Web App) permite instalarla en los celulares de los porteros y bartenders sin pasar por App Store/Play Store, y usar la cámara nativa del teléfono para leer los QR ( html5-qrcode ).
Backend:   Node.js (Fastify o Express) o NestJS  (TypeScript para tipado estricto en cálculos financieros).
Base de Datos:   PostgreSQL  (ideal para transacciones ACID en inventario y contabilidad).
Almacenamiento / Caché:   Redis  (para validar QRs en milisegundos en puerta y evitar doble ingreso).
Envío de Correos (Dynamic Sender):   Resend, Amazon SES o Nodemailer (SMTP propio)  configurado con subdominios o  Reply-To  dinámico según la productora.
2. Flujo de Inicialización (El Popup de Configuración Única)
Cuando se crea un evento nuevo y se entra por primera vez al panel, el sistema intercepta la navegación mediante un  Guard/Middleware  verificando la bandera  is_configured === false  en la tabla  events .
Lógica del Modal Bloqueante (1 sola vez por evento):
Input 1:  Nombre de la Productora (ej.  Renton Producciones ,  Psicosis Events ).
Input 2:  Correo de contacto/respuesta de la productora (ej.  entradas@productora.cl ).
Input 3:  Nombre y Fecha del Evento.
Switch/Toggle Principal:   ¿Este evento contará con barra de tragos?  ( has_bar: boolean ).
Acción al guardar:
Se actualiza  is_configured = true . Este modal no vuelve a aparecer jamás para este evento (a menos que el administrador entre a  Configuración Avanzada ).
Si  has_bar === true :  Se habilita en el menú lateral el módulo  "Control de Barra & Stock"  y redirige inmediatamente al formulario de carga inicial de inventario (Botellas, latas, hielo, vasos, insumos) antes de abrir las ventas.
Si  has_bar === false :  El módulo de barra queda oculto y desactivado en la interfaz y en los cálculos de cierre.
3. Diseño de Base de Datos (PostgreSQL)
SQL
-- 1. Productoras (Multi-tenant)
CREATE   TABLE  producers (
id UUID  PRIMARY  KEY  DEFAULT  gen_random_uuid(),
name  VARCHAR ( 150 )  NOT   NULL ,
contact_email  VARCHAR ( 150 )  NOT   NULL ,
logo_url TEXT,
created_at  TIMESTAMP   DEFAULT  NOW()
);
-- 2. Eventos (Con el estado del Popup inicial)
CREATE   TABLE  events (
id UUID  PRIMARY  KEY  DEFAULT  gen_random_uuid(),
producer_id UUID  REFERENCES  producers(id)  ON   DELETE  CASCADE,
name  VARCHAR ( 150 )  NOT   NULL ,
event_date  TIMESTAMP   NOT   NULL ,
has_bar  BOOLEAN   DEFAULT   FALSE ,
is_configured  BOOLEAN   DEFAULT   FALSE ,  -- Controla el popup de 1 sola vez
created_at  TIMESTAMP   DEFAULT  NOW()
);
-- 3. Tipos de Entradas (Preventa 1, Preventa 2, Puerta, VIP)
CREATE   TABLE  ticket_tiers (
id UUID  PRIMARY  KEY  DEFAULT  gen_random_uuid(),
event_id UUID  REFERENCES  events(id)  ON   DELETE  CASCADE,
name  VARCHAR ( 100 )  NOT   NULL ,
price  DECIMAL ( 10 ,  2 )  NOT   NULL ,
capacity  INT   NOT   NULL
);
-- 4. Asistentes y Control QR
CREATE   TABLE  attendees (
id UUID  PRIMARY  KEY  DEFAULT  gen_random_uuid(),
event_id UUID  REFERENCES  events(id)  ON   DELETE  CASCADE,
tier_id UUID  REFERENCES  ticket_tiers(id),
full_name  VARCHAR ( 150 )  NOT   NULL ,
rut  VARCHAR ( 20 )  NOT   NULL ,  -- Validado con dígito verificador chileno
email  VARCHAR ( 150 )  NOT   NULL ,
price_paid  DECIMAL ( 10 ,  2 )  NOT   NULL ,
qr_token  VARCHAR ( 255 )  UNIQUE   NOT   NULL ,  -- Hash criptográfico único
is_checked_in  BOOLEAN   DEFAULT   FALSE ,
checked_in_at  TIMESTAMP ,
created_at  TIMESTAMP   DEFAULT  NOW()
);
-- 5. Finanzas: Ingresos Extras y Gastos (Egresos)
CREATE   TABLE  transactions (
id UUID  PRIMARY  KEY  DEFAULT  gen_random_uuid(),
event_id UUID  REFERENCES  events(id)  ON   DELETE  CASCADE,
type  VARCHAR ( 10 )  CHECK  (type  IN  ( 'INCOME' ,  'EXPENSE' )),
category  VARCHAR ( 100 )  NOT   NULL ,  -- Ej: DJs, Sonido, Local, Auspicios, Venta Barra
description TEXT,
amount  DECIMAL ( 12 ,  2 )  NOT   NULL ,
payment_method  VARCHAR ( 50 ),  -- Transferencia, Efectivo, Débito
created_at  TIMESTAMP   DEFAULT  NOW()
);
-- 6. Stock de Barra (Solo activo si events.has_bar = TRUE)
CREATE   TABLE  bar_inventory (
id UUID  PRIMARY  KEY  DEFAULT  gen_random_uuid(),
event_id UUID  REFERENCES  events(id)  ON   DELETE  CASCADE,
product_name  VARCHAR ( 150 )  NOT   NULL ,  -- Ej: Pisco Alto del Carmen 1L, Red Bull
unit_cost  DECIMAL ( 10 ,  2 )  NOT   NULL ,   -- Costo de compra (va a gastos)
sale_price  DECIMAL ( 10 ,  2 )  NOT   NULL ,  -- Precio venta vaso/botella
initial_stock  INT   NOT   NULL ,
current_stock  INT   NOT   NULL ,
waste_stock  INT   DEFAULT   0   -- Merma o cortesías DJ/Staff
);
4. Módulos Funcionales Detallados
A. Módulo de Asistentes, Tickets y Envío Dinámico de QR
Registro de Asistente:
Al ingresar a la persona (Nombre, RUT, Email, Tipo de entrada y Precio pagado), el sistema  valida automáticamente el formato y dígito verificador del RUT  (Módulo 11) para evitar errores de tipeo.
Automáticamente se registra un ingreso en el módulo financiero por el valor de esa entrada.
Generación de QR Seguro:
No guardes el RUT en texto plano dentro del QR (cualquiera podría falsificarlo). Genera un token firmado ( JWT  o  HMAC-SHA256  con el  attendee_id  +  event_id ).
Correo Personalizado por Productora:
Al emitir el ticket, el backend dispara el correo usando el nombre de la productora configurada en el popup inicial:
Remitente ( From ):   "${producer.name}" <tickets@tudominio.cl>
Responder a ( Reply-To ):   ${producer.contact_email}
Cuerpo:  Incluye la imagen del QR incrustada en Base64/CID, nombre del evento, nombre del asistente, RUT y categoría de entrada.
B. Escáner de Puerta (Validación de Identidad)
Una vista optimizada para móvil con la cámara abierta al 100%:
Al leer el QR:
Estado 1 (Válido):  Pantalla  VERDE  gigante. Muestra en letra grande:
NOMBRE:  Juan Pérez González
RUT:  18.456.789-K  (Para cotejar visualmente con su cédula de identidad en puerta)
ENTRADA:  Preventa 1 - Pagada
Marca  is_checked_in = true  y guarda la hora exacta.
Estado 2 (Ya ingresó):  Pantalla  AMARILLA/ROJA  de alerta:  "¡ALERTA! Este QR ya fue escaneado a las 01:42 AM por Juan Pérez (18.456.789-K)" .
Estado 3 (Inválido/Otro Evento):  Pantalla  ROJA :  "Código QR no corresponde a este evento" .
C. Módulo de Control de Barra (Condicional)
Carga Inicial:  Se ingresa cantidad de botellas/insumos y costo de compra (el costo total de compra de mercadería se suma automáticamente a los  Gastos  del evento).
Cierre / Arqueo de Barra:  Al terminar la fiesta, se ingresa el  Stock Final Físico  (lo que sobró en botellas cerradas/abiertas).
El sistema calcula:  (Stock Inicial - Stock Final - Mermas/Cortesías) = Unidades Vendidas .
Multiplica por el precio de venta para calcular el  Ingreso Teórico de Barra  y lo compara contra lo recaudado en cajas/POS para detectar robos o descuadres de bartenders.
D. Módulo de Ingresos, Gastos y Balance en Tiempo Real
Panel Superior (KPIs):
Ingresos Totales:  (Suma automática de Entradas vendidas + Ventas de Barra + Auspicios/Otros).
Gastos Totales:  (Suma de costos de Barra + DJs + Arriendo Local + Seguridad + Sonido/Iluminación + Permisos).
Utilidad Neta Actual:   Ingresos - Gastos  (con indicador verde si ya pasaste el punto de equilibrio o rojo si aún falta vender entradas para cubrir costos).
Registro Rápido:  Botón flotante  + Gasto  y  + Ingreso  con categorías predefinidas para productoras y opción de subir foto de boleta/comprobante.
5. Código Base: Lógica de RUT, QR y Correo Dinámico (Node.js)
Aquí tienes la función lista para el backend que valida el RUT, genera el QR y envía el correo con el nombre de la productora:
JavaScript
import  QRCode  from   'qrcode' ;
import  crypto  from   'crypto' ;
import  nodemailer  from   'nodemailer' ;
// 1. Validador de RUT Chileno (Módulo 11)
export    function   validarRUT ( rut )  {
const  cleanRut = rut.replace( /[^0-9kK]/g ,  '' ).toUpperCase();
if  (cleanRut.length <  8 )  return   false ;
const  body = cleanRut.slice( 0 , - 1 );
const  dv = cleanRut.slice(- 1 );
let  sum =  0 ;
let  multiplier =  2 ;
for  ( let  i = body.length -  1 ; i >=  0 ; i--) {
sum +=  parseInt (body[i]) * multiplier;
multiplier = multiplier ===  7  ?  2  : multiplier +  1 ;
}
const  expectedDv =  11  - (sum %  11 );
const  calculatedDv = expectedDv ===  11  ?  '0'  : expectedDv ===  10  ?  'K'  : expectedDv.toString();
return  dv === calculatedDv;
}
// 2. Generar Ticket QR y Enviar Correo con Nombre de Productora
export   async    function   emitirYEnviarEntrada ( { attendee, event, producer } )  {
if  (!validarRUT(attendee.rut)) {
throw   new   Error ( 'El RUT ingresado no es válido.' );
}
// Crear firma única para evitar falsificación de QR
const  signature = crypto
.createHmac( 'sha256' , process.env.QR_SECRET_KEY)
.update( ` ${event.id} : ${attendee.id} : ${attendee.rut} ` )
.digest( 'hex' )
.slice( 0 ,  16 );
const  qrPayload =  JSON .stringify({
tid : attendee.id,
eid : event.id,
sig : signature
});
// Generar imagen QR en Base64
const  qrDataUrl =  await  QRCode.toDataURL(qrPayload, {  width :  350 ,  margin :  2  });
// Configurar transporte SMTP
const  transporter = nodemailer.createTransport({
host : process.env.SMTP_HOST,
port :  587 ,
auth : {  user : process.env.SMTP_USER,  pass : process.env.SMTP_PASS }
});
// Enviar correo personalizado con el nombre de la productora
await  transporter.sendMail({
from :  `" ${producer.name} " < ${process.env.SMTP_FROM_EMAIL} >` ,
replyTo : producer.contact_email,
to : attendee.email,
subject :  `Tu entrada para  ${event.name}  -  ${producer.name} ` ,
html :  `
<div style="font-family: Arial, sans-serif; max-width: 500px; margin: auto; border: 1px solid #222; border-radius: 12px; padding: 24px; background: #111; color: #fff;">
<h2 style="color: #00e676; margin-bottom: 4px;"> ${producer.name} </h2>
<p style="color: #aaa; margin-top: 0;">Presenta: <strong> ${event.name} </strong></p>
<hr style="border-color: #333;" />
<p><strong>Asistente:</strong>  ${attendee.full_name} </p>
<p><strong>RUT (Presentar cédula en puerta):</strong>  ${attendee.rut} </p>
<p><strong>Tipo de Entrada:</strong>  ${attendee.tier_name} </p>
<div style="text-align: center; background: #fff; padding: 16px; border-radius: 8px; margin: 20px 0;">
<img src="cid:ticketqr" alt="Código QR de Acceso" style="width: 220px; height: 220px;" />
</div>
<p style="font-size: 12px; color: #888; text-align: center;">
Este código QR es personal e intransferible. Se solicitará tu carnet de identidad para validar tu RUT al ingresar.
</p>
</div>
` ,
attachments : [{
filename :  'entrada-qr.png' ,
path : qrDataUrl,
cid :  'ticketqr'
}]
});
return  { qrPayload, signature };
}
